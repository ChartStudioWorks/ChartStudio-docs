# 第三方谱面格式解析

::: warning 注意
本文的第三方格式说明基于现有样例和实际编辑器测试。格式可能因编辑器或版本不同而异，文中会标出尚未验证的范围。

## Malody 谱面

### `.mc` 示例结构：

```jsonc
{
  "meta": {
    "$ver": 0,                            // 版本
    "creator": "谱师名",
    "background": "background.jpg",
    "version": "Lv.15",                   // 谱面名称
    "preview": 233,                       // 预览起始时间
    "id": 0,
    "mode": 0,                            // 当前样本中为 0，对应下落式 Key 模式
    "time": 1742122599,                   // 最后修改时间(戳)
    "song": {                             // 歌曲元信息
      "title": "歌曲名",
      "artist": "曲师名",
      "id": 0
    },
    "mode_ext": {
      "column": 6,                        // 轨道数，这里是 6 轨
      "bar_begin": 0                      // 可能与起始小节有关，当前不使用
    }
  },

  "time": [                               // BPM 表
    {
      "beat": [0, 0, 1],                  // [整数拍, 分子, 分母]
      "bpm": 170.0
    }
  ],

  "effect": [                             // 变速表
    {
      "beat": [1, 0, 1],
      "scroll": 1.0                       // 相对流速
    },
    {
      "beat": [60, 0, 4],
      "scroll": 0.0
    },
    {
      "beat": [61, 0, 4],
      "scroll": 6.0
    }
  ],

  "note": [                               // 音符数据
    {
      "beat": [4, 2, 4],
      "column": 0                         // 轨道编号
    },
    {
      "beat": [8, 0, 4],
      "endbeat": [9, 0, 4],               // 长条尾
      "column": 3
    },

    // 特殊音频对象，可近似理解为 meta_ext，属于极少数事件，而我并不想处理这坨东西
    {
      "beat": [0, 0, 1],
      "sound": "audio.ogg",               // 主音频文件名
      "vol": 100,                         // 音量
      "offset": 349,                      // 音频偏移
      "type": 1                           // 对象类型，当前具体枚举含义未完全确认
    }
  ],

  "extra": {                              // 补充字段，非核心信息，当前不使用
    "test": {
      "divide": 4,
      "speed": 100,
      "save": 0,
      "lock": 0,
      "edit_mode": 0
    }
  }
}
```

### 补充说明

`beat` 使用 `[整数拍, 分子, 分母]` 表示，换算为 `整数拍 + 分子 / 分母`。

带有 `"endbeat"` 的 `note` 为长条
## DCS 谱面

### `musicInfo.json` 示例结构

```jsonc
{
    //uuid字段, 未发现引用
    "uuid": "3de894700cc245c4a1bb404071080915",
    "name": "曲名",
    "autor": "曲师",
    "bpm": 236,               // 默认bpm
    "firstTime": 0.22,        // 谱面偏移 / 歌曲起始时间(s)
    "bpmList": {              // bpm变化表，此值允许为空
        "0": 236
    },
    "c_time": "2026/4/11 14:29:48",     // 创建时间
    "e_time": "2026/4/11 14:29:48"      // 编辑时间
}
```

### 谱面文件示例结构
```txt
1-0
1-0.5
4-1
4-1.5
1-2
1-2.5
4-3
4-3.5
2-4
2-4.5
6-24-24.5
```
### 变速文件示例结构
```txt
26.5,0.9
30.5,1
286.75,0
287,1
```


### 音符编码规则

以下格式和顺序行为根据实际编辑器测试整理。尚未验证所有 DCS 编辑器版本，因此不应将观察结果视为所有版本都一致的保证。

| 原始记录 | 含义 |
|---|---|
| `1-0.5` | 第 1 轨 Tap，位于 0.5 拍。 |
| `13-0.5` | 第 1、3 轨同时 Tap，位于 0.5 拍。 |
| `31-0.5` | 第 3、1 轨同时 Tap，位于 0.5 拍；与 `13-0.5` 表示相同的音符位置和类型。 |
| `2-1.5-2` | 第 2 轨 Hold，起始于 1.5 拍，结束于 2 拍。 |
| `23-1.5-2` | 第 2、3 轨同时 Hold，起始于 1.5 拍，结束于 2 拍。 |

轨道编码由一个或两个 `1～6` 的数字字符组成。两位编码中的每个数字各自表示一个轨道；例如 `13` 表示第 1、3 轨，不能把 `13` 当作一个整数轨道编号。`13` 与 `31` 的轨道集合相同，音符位置和类型等价。

同一条双轨 Hold 只有在两个音符的起始节拍和结束节拍都相同时才成立。起始节拍相同但结束节拍不同的 Hold 必须分别记录；同拍的 Tap 与 Hold 也分别记录。三押 Tap 可以由一条双轨记录和一条单轨记录组成，例如 `13-0.5` 加 `5-0.5`。

### 已观察到的记录顺序

- DCS 文件中的记录按起始节拍升序排列。
- 同拍记录中的轨道顺序，以及多条同拍记录之间的顺序，不保证升序；测试中观察到它们可能受音符创建顺序影响。
- 实验没有确认 DCS 的内部排序算法，因此不对其实现方式作推断。

### 变速文件

以 `26.5,0.9` 为例，该字段即代表“在`26.5`拍时，将流速调整为正常值的`0.9`倍”。
