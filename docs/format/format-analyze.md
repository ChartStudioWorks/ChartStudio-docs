## Malody 谱面

### `.mc` 示例结构：

```jsonc
{
  "meta": {
    "$ver": 0,                            // 版本
    "creator": "谱师名",
    "background": "background.jpg",
    "version": "Lv.15",                   // 谱面名称
    "preview": 233,                       // 预览起始时间
    "id": 0,
    "mode": 0,                            // 当前样本中为 0，对应下落式 Key 模式
    "time": 1742122599,                   // 最后修改时间(戳)
    "song": {                             // 歌曲元信息
      "title": "歌曲名",
      "artist": "曲师名",
      "id": 0,
      "file": "audio.ogg"                 // 可选音频引用
    },
    "mode_ext": {
      "column": 6,                        // 轨道数，这里是 6 轨
      "bar_begin": 0                      // 可能与起始小节有关，当前不使用
    }
  },

  "time": [                               // BPM 表
    {
      "beat": [0, 0, 1],                  // [小节索引, 分子, 分母]
      "bpm": 170.0
    }
  ],

  "effect": [                             // 变速表
    {
      "beat": [1, 0, 1],
      "scroll": 1.0                       // 相对流速
    },
    {
      "beat": [60, 0, 4],
      "scroll": 0.0
    },
    {
      "beat": [61, 0, 4],
      "scroll": 6.0
    }
  ],

  "note": [                               // 音符数据；也可能包含音频事件
    {
      "beat": [4, 2, 4],
      "column": 0                         // 轨道编号
    },
    {
      "beat": [8, 0, 4],
      "endbeat": [9, 0, 4],               // 长条尾
      "column": 3
    }
  ],

  "extra": {                              // 补充字段，非核心信息，当前不使用
    "test": {
      "divide": 4,
      "speed": 100,
      "save": 0,
      "lock": 0,
      "edit_mode": 0
    }
  }
}
```

### 节拍三元组

在已通过编辑器实测验证的 4/4 Key 谱面中，`beat` 使用 `[bar, numerator, denominator]`，表示从 `0` 开始的小节索引及小节内的分数位置。换算到 CSC 的四分音符拍坐标时使用：

```text
CSC beat = (bar + numerator / denominator) × 4
```

| Malody 三元组 | CSC `beat` |
| --- | --- |
| `[0, 0, 4]` | `0` |
| `[0, 1, 4]` | `1` |
| `[0, 2, 4]` | `2` |
| `[0, 3, 4]` | `3` |
| `[1, 0, 4]` | `4` |
| `[0, 1, 32]` | `0.125` |

Tap 的 `beat`、Hold 的 `beat` 与 `endbeat`、BPM 的 `time[].beat`、Scroll 的 `effect[].beat` 使用同一种坐标表示。带有 `endbeat` 的可击打音符为 Hold。

::: warning 拍号验证边界
上述乘以 `4` 的换算仅在 4/4 谱面中得到实测验证。当前 ChartStudio 不识别并换算独立拍号信息，非 4/4 时间轴尚未验证，不能据此保证其他拍号的转换结果。导入校验与精度说明见[Malody 时间事件与错误处理](/import/import-mapping-rules#malody-时间事件与错误处理)。
:::

### `meta.song` 曲目字段

| 字段 | 含义 |
|---|---|
| `meta.song.title` | 歌曲标题。 |
| `meta.song.artist` | 艺术家。 |
| `meta.song.id` | 歌曲关联标识；其具体取值语义尚未完整验证。样本中的 `0` 不据此判定为非法。 |
| `meta.song.file` | 可选的歌曲音频文件引用。该字段可能不存在；缺少它不代表谱面没有音频。 |

### BGM 音频事件

Malody Key 模式的 `note` 是数组，其中可以同时出现可击打音符和音频事件。以下为样本中观察到的 BGM 事件：

```json
{
  "note": [
    {
      "beat": [0, 0, 1],
      "sound": "audio.ogg",
      "vol": 100,
      "offset": 259,
      "type": 1
    }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `beat` | 事件所在的节拍位置，不是毫秒时间。 |
| `sound` | 事件引用的音频文件。 |
| `vol` | 音量信息。 |
| `offset` | 音频偏移，单位为毫秒；该字段在样本中并非必需。 |
| `type` | 事件类型；当前 Key 模式样本中的 `type: 1` 表示此类 BGM 事件，不据此推断其他 Malody 模式中的含义。 |

当前确认的 BGM 事件不是可击打的 Tap 或 Hold，不能直接映射到 CSC 的 `notes`。

普通轨道音符也可能带有 `sound`，表示 Keysound 关联；不能只凭 `sound` 字段将其归为 BGM。当前导入分类与 Keysound 支持范围见[Malody 音频资源与 Offset](/import/import-mapping-rules#malody-音频资源与-offset)。

::: info BGM Offset 实测
用户在 Malody 编辑器保存并试听后确认：把第 0 拍 BGM `offset` 从 `259` 改为 `1259` 毫秒，音乐延后播放 `1000` 毫秒。此正值方向与 CSC 一致，映射时不取反，也不转换单位。负数的游戏内播放行为尚未单独实测；程序的兼容处理见[Malody Offset 映射](/import/import-mapping-rules#malody-offset-映射)。
:::

### 有限样本观察

::: info 样本范围
此前检查的一批 32 个压缩包中，31 个包含 Malody `.mc`，合计 41 张 `.mc`；41 张均观察到 BGM `sound` 事件，其中 34 张的 BGM 事件带有 `offset`，7 张没有。19 张包含 `meta.song.file`；在同时包含 `meta.song.file` 和 BGM `sound` 的样本中，文件名均一致。41 张 `.mc` 均未发现 `meta.song.offset`。

以上仅描述这批有限样本，不代表所有 Malody 文件或版本的格式保证。
:::
## DCS 谱面

### `musicInfo.json` 示例结构

```jsonc
{
    //uuid字段, 未发现引用
    "uuid": "3de894700cc245c4a1bb404071080915",
    "name": "曲名",
    "autor": "曲师",
    "bpm": 236,               // 基础 BPM
    "firstTime": 0.22,        // 曲目偏移，单位秒
    "bpmList": {              // BPM 事件表，{} 表示空表
        "0": 236
    },
    "c_time": "2026/4/11 14:29:48",     // 创建时间
    "e_time": "2026/4/11 14:29:48"      // 编辑时间
}
```

| 字段 | 用途 |
| --- | --- |
| `name`、`autor` | 曲名与曲师；`autor` 是原始格式中的实际拼写。 |
| `bpm` | 基础 BPM。 |
| `bpmList` | 以节拍坐标为键、BPM 为值的事件表；零拍值可以与基础 BPM 不同。 |
| `firstTime` | 秒单位的时间偏移，不是节拍数。 |
| `uuid`、`c_time`、`e_time` | 样本中的其他元信息，ChartStudio 当前不映射这些字段。 |

ChartStudio 对必需键及 `firstTime` 的校验见[DCS 导入限制](/import/import-format-rules#dcs-限制)，与 CSC 的单位换算见[DCS 时间字段映射](/import/import-mapping-rules#dcs-时间字段映射)。

### 音符编码规则

以下格式和顺序行为根据实际编辑器测试整理。尚未验证所有 DCS 编辑器版本，因此不应将观察结果视为所有版本都一致的保证。

| 原始记录 | 含义 |
|---|---|
| `1-0.5` | 第 1 轨 Tap，位于 0.5 拍。 |
| `13-0.5` | 第 1、3 轨同时 Tap，位于 0.5 拍。 |
| `31-0.5` | 第 3、1 轨同时 Tap，位于 0.5 拍；与 `13-0.5` 表示相同的音符位置和类型。 |
| `2-1.5-2` | 第 2 轨 Hold，起始于 1.5 拍，结束于 2 拍。 |
| `23-1.5-2` | 第 2、3 轨同时 Hold，起始于 1.5 拍，结束于 2 拍。 |

轨道编码由一个或两个 `1～6` 的数字字符组成。两位编码中的每个数字各自表示一个轨道；例如 `13` 表示第 1、3 轨，不能把 `13` 当作一个整数轨道编号。`13` 与 `31` 的轨道集合相同，音符位置和类型等价。

同一条双轨 Hold 只有在两个音符的起始节拍和结束节拍都相同时才成立。起始节拍相同但结束节拍不同的 Hold 必须分别记录；同拍的 Tap 与 Hold 也分别记录。三押 Tap 可以由一条双轨记录和一条单轨记录组成，例如 `13-0.5` 加 `5-0.5`。

### 已观察到的记录顺序

- DCS 文件中的记录按起始节拍升序排列。
- 同拍记录中的轨道顺序，以及多条同拍记录之间的顺序，不保证升序；测试中观察到它们可能受音符创建顺序影响。
- 实验没有确认 DCS 的内部排序算法，因此不对其实现方式作推断。

### 变速文件

以 `26.5,0.9` 为例，该字段即代表“在`26.5`拍时，将流速调整为正常值的`0.9`倍”。

每个 `_sv.txt` 属于对应名称的难度谱面，记录使用 `beat,value`。`beat` 是节拍坐标，`value` 是倍率；已知样本中 `0` 倍率会保留。ChartStudio 的校验、重复节拍与导出顺序见[DCS Scroll 映射](/import/import-mapping-rules#dcs-scroll-映射)，负值及重复事件在 DCS 中的游戏内解释尚未验证。
